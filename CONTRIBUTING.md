# Contributing to Lookout

Thanks for helping make project maintenance easier.

- Work on a feature branch and open a PR against main.
- Prefer small provider-agnostic components and pure assessment rules.
- Keep API permissions read-only until the action and approval model exists.
- Add tests for rules, date handling, partial provider data and failure behaviour.
- Never commit tokens, database URLs, private project observations or credentials.
- Use British English in documentation and interface text.
- Run npm run typecheck, npm test and npm run build before asking for review.

Design discussions and issues are welcome, including suggestions for new Git hosts and deployment providers. Lookout's goal is to complement existing issue trackers, not replace them.
